B11 / B13 / B14 收口：Rust bridge、`lan config` 子命令族、模板选项单点（设计文档 §3.5 / §6.5 / §11）。

**B11：Rust bridge（`lan-rs-bridge`，零新增产物）**

- `lan` 二进制新增隐藏模式 `lan __lania_rs_bridge`：同一二进制说 jsonl 协议，
  实现 `lint.clippy`（`cargo clippy --message-format=json` → 全字段 `Diagnostic`）与
  `build.rust`（exec `cargo build`，stdout/stderr 逐行 `event.diag`）。
- **不需要新的 npm 平台包**：`BridgeLaunchSpec` 指向 `current_exe`，顺带满足 `--version` 自报版本。
- `lint` / `build` 的运行时分流补上 Rust；`LANIA_RS_BRIDGE` 可覆盖/制造不可用场景。
- 工具失败（`cargo` 缺失、退出码非 0 且解析不出诊断）产出一条可见 error 诊断，
  不再静默“0 errors”通过。

**B13：`lan config` 子命令族（项目 `lan.config.ts`）**

- 新增 `lan config init` / `doctor` / `sync`；`lan config set` 变为双作用域：
  `locale` / `log.timestamps` / `output.mode` 仍是全局偏好，其余按项目配置路径处理。
- **只有纯数据配置才允许程序化改写**：源文件含 `import` / `require(` / `=>` / `function`
  时只返回建议片段、一个字节都不写（`set` / `sync --write` 都遵守，`--force` 也不绕过）。
- `init` 在项目能解析到 `lania` 包时写 `defineConfig(...)` 模板，否则写普通
  `export default {…}` —— 新项目不会因为 import 一个没装的包而配置加载失败。
- `doctor` 只读：`configPath` / `runtime{declared,detected,effective,source}` /
  `runtimes` / `lintTools` / `pureData` / `writable` / `validationErrors` / `issues[]`，
  问题同时以 warning 打到终端。
- 顶层字段白名单收敛为 `lania_config::known_config_fields()`（validate 与写入共用）。

**B14：模板选项统一到 `RuntimeToolchain.presentation`**

- `@lania-cli-v2/templates/presentation.ts` 是模板提问选项（包管理器 / lint / 测试工具 +
  默认值）的唯一字面量来源，覆盖 7 个运行时；`toolchain.ts` 组合成
  `RuntimeToolchain.presentation` 并由 `toolchain.describe` 暴露给 Rust / doctor。
- 5 个模板的 `*_CHOICES`、以及 4 个 Node 模板的工程化工具列表改为从 presentation 派生，
  删掉重复字面量；模板侧仍有「value 集合 == presentation」的等价性测试，漂移即红。
- **`create` 产出的项目配置统一为 `lan.config.ts`**（10 个 ejs 模板 + 4 个 Rust 兜底），
  与 §6.5「`.ts` 是唯一官方格式」一致。

**顺带的验收补齐**

- 运行时判定新增「有提示」：多信号项目（如 `deno.json` + `package.json`）会输出
  「detected …; using `deno` — pass `--runtime <id>` to override」。
- 新增跨语言一致性锁：Rust 的 `FEATURE_PRIORITY` 与 TS `DETECTION_PRIORITY` 逐条比对；
  Python bridge 与 TS 参考解析器用同一份 ruff fixture + golden 双向断言。
- `lan dev` 的 `[app]` 实时日志与 `--quiet-app` 有 e2e；`.ts` 配置加载失败有 e2e。
