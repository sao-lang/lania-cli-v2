## A. 代码正确性 / 契约违背（VERIFIED）

### A1 🔴 `from_cache` 语义写反（runex 缓存命中判定）

- 位置：`packages/products/runex/rust/runex-core/src/store.rs:189,194-195,207-208,258`
- 现象：`let mut from_cache = true;` 初始为 true；命中缓存 `if cached.is_file()` 里却 `from_cache = false`；未命中下载分支 `if !cached.is_file()` 也 `from_cache = false`。
- 后果：无论是否命中缓存，`from_cache` 恒为 false（只要走下载循环）。`InstallOutcome.from_cache` 对外语义完全错误，上层据此判断"是否用了缓存"会出错；设计文档 self-managed-runtime-manager §17.2 #1 已记录但未修。
- 改法：初值改 `false`；命中缓存分支设 `true`。即 `let mut from_cache = false;`，`if cached.is_file() { from_cache = true; ... }`，下载分支保持 false。

### A2 🔴 幽灵 bridge 能力 `hooks.resolveLifecycle`

- 位置：`packages/distribution/cli/rust/lania-host/src/runtime/catalog.rs:33`
- 现象：内建能力清单声明 lifecycle 提供 `hooks.resolveLifecycle`，全仓 grep 仅此一处，TS 从未实现（TS 实现的是 `hooks.invoke` / `hooks.invokeInline`）。
- 后果：能力发现/握手预览对外暴露不存在的方法，调用方拿到 `E_METHOD_NOT_FOUND`；且整张 catalog 与真实 36 个方法严重漂移（缺 product._、agent._、toolchain.describe、hooks.invokeInline、addTemplate.render、addGenerator.list，包名还写 dead `@lania-cli/node-bridge` 共 21 处）。
- 改法：删除 `hooks.resolveLifecycle`；补全真实方法；包名统一 `@lania-cli-v2/bridge-slice-*`。

### A3 🟡 compiler web fallback 伪造成功（契约违背，但属刻意取舍）

- 位置：`compiler/ts/src/plugins/compiler.ts:80-88,119-126` + `compiler-shared.ts:105-178,180-220`
- 现象：web runtime 下 worker 失败/异常被 catch 吞掉后返回 `buildResult(...,'fallback')` / `fallbackDevResult`，内含 `compilerDoneEvent(success=true)` 与假 `dist/index.js`、`http://host:port` ready 事件。
- 后果：与 README「工具链缺失时 fail-fast，不伪造」冲突；test-report(11-11) 已标记"需要产品决策"，本次代码已改非 web 为 fail-fast，但 web 仍兜底。用户 web 项目构建失败会看到"成功"。
- 判定：非 web 已修 ✅；web 兜底是刻意保留（注释明示）——**降级为 Should，需产品决策是否翻转**。

### A4 🟡 product 包死代码副本

- 位置：`packages/commands/product/rust/src/dev.rs:27,45`（`DevCommandHandler` + `build_request`），registry.rs:21-29 只注册 `ProductDevCommandHandler`
- 现象：源码注释自认"完整副本，仅 ProductDevCommandHandler 被注册使用"。
- 后果：两份 dev/build 逻辑漂移风险；`resolve_dev_exit_code` 对缺 `success` 字段默认判成功（`unwrap_or(true)`，:36）。
- 改法：删除未注册的 `DevCommandHandler` 副本，或提取共享函数。

### A5 🟡 config 写盘静默吞损坏文件

- 位置：`lania-command-config/src/lib.rs:163-195`（`save_main_override`）
- 现象：`serde_json::from_str(...).unwrap_or_default()`，主覆盖段文件损坏时静默变空对象后覆盖写回。
- 后果：用户配置被静默清空。`set` 路径（:518-562）仅靠 `ConfigKey.parse` 校验。
- 改法：损坏时返回错误而非 default，或备份后重写。
