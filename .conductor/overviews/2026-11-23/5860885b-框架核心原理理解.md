# 框架核心原理理解 — 只读结论

- 场景 10 代码库理解；只读，未改任何源码。
- 核心：三层双运行时。launcher 分发 → Rust host 控制 → Node Bridge 扩展 → 12 切片/模板/动态命令。原则「控制权留 Rust，扩展权给 Node，风险由 Rust 裁决」（`docs/architecture/模块设计与通信总览.zh-CN.md:43-64`）。
- 已有官方学习地图 `docs/guides/learning-map.zh-CN.md`，但其中部分路径 stale（如 `packages/commands/dev`、`host-core/src/runtime.rs` 已不存在）。

## 追加：多运行时通信与推荐学习点（只读）

- **两套通信并存**（关键事实，勿混淆）：
  1. 生产中 1:1 的 Rust↔Node stdio/jsonl：`lania-host/src/execution/bridge_api.rs`、`bridge-runtime/ts/src/{entry/stdio,core/host-rpc}.ts`。Node→Rust 反向调用走 hostCall + host.\* namespace。
  2. 实验中立的 Bridge Hub（语言中立消息总线）：`products/bridge-hub`，4 个 Rust crate（core/bus/protocol/host）+ 5 语言 adaptor（ts/py/go/dart/rust）。帧协议唯一事实源 `protocol/golden/protocol.json`（8 种帧，busInvariant 禁止 language/runtime 字段）。Hub 实现 `lania-bridge-bus/src/hub.rs:37-400`（端点表/能力表/主题表/pending 表，pump_once 同步驱动，route_request 按 capability round-robin）。
- **现状边界**：Hub 已接线为优先链路，但 `provider.rs:129-149` 的 register_language 实际只 attach 进程内 Rust/EchoHandler 端点，**不 spawn 真实语言子进程**；跨语言真连通只在 `lania-bridge-host/tests/stdio_endpoints.rs` 集成测试中由 attach_python/attach_node 等验证。1:1 NodeBridgeClient 作为兼容回落刻意保留（bridge_setup.rs:49-70）。来源：`docs/design/bridge-layer.zh-CN.md:154,197-208,231-273`。
- 生成器 `protocol/gen.mjs` 从 schema 一次生成 5 语言协议绑定+runtime 骨架（传输/id/心跳/错误），手写 adaptor 只写 manifest + onRequest/onEvent。

### 修正确认（用户追问「Hub 是否真的作为桥接被使用」）

- **结论：Hub 已接入调用链但并未承载真实业务流量**。证据链：
  1. `lania-host/src/execution/bridge_api.rs:93-121`：`call_bridge` 每次先试 `provider.call(method, params)`，未命中（E_METHOD_NOT_FOUND）就回落 `dispatch_bridge_request`（1:1 NodeBridgeClient）。
  2. `bridge-hub/adaptors/rust/endpoint.rs:43`：`PROVIDES = ["echo.ping","echo.upper"]`——生产注入的 provider 只声明两个 echo 能力（`provider.rs:142` announce）。
  3. 真实业务 method 是 `compiler.dev` / `compiler.build` / `lint.run` / `agent.prompt` / `config.*` 等，无一是 echo.\*，因此**每次真实调用必然回落**。
  4. `attach_python/node/go/dart()` 真·跨进程接入仅出现在 `lania-bridge-host/tests/stdio_endpoints.rs`，生产装配 `bridge_setup.rs:44-70` 走的是 `register_language` → 进程内 EchoHandler，不 spawn 子进程（见 `provider.rs:11-15,139-148`）。
  5. `LANIA_BRIDGE_MODE=hub` 在代码中仅 `bridge-runtime/ts/src/entry/stdio.ts:29` 一处判断切 `hub-stdio.ts`；默认 1:1。
- 准确定性：Hub = 已搭好的基础设施 + echo 级闭环 + 集成测试验证；真实跨语言桥接尚未切换过来。文档「已接线为优先链路」只描述调用顺序，不等于承载流量。
