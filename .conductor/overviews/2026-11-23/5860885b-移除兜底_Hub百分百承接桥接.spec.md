# Design Spec / 2026-11-23 / 移除兜底，Hub 100% 承接桥接

## 1. 背景与目标

当前 `lania-cli-v2` 的桥接层是双轨：`call_bridge` 先试 `BridgeProvider`（Hub），失败回落 1:1 `NodeBridgeClient`，并有 `LANIA_BRIDGE_MODE` 开关。用户明确要求不做兼容、不打补丁、不要兜底，让 Hub 100% 承接桥接，所有语言运行时（Node/Python/Go/Dart/Rust）都作为 Hub 端点接入。

## 2. 用户原话（需求来源）

- 「不做兼容 不打补丁，100% 用它承接桥接，不要兜底了，让所有运行时都使用它桥接」
- 控制面决策：扩展协议承载事件（进度/日志流、长任务 shutdown）
- 运行时范围：全部语言端点
- 清理边界：删 call_bridge 回落分支、删 LANIA_BRIDGE_MODE 开关、删 1:1 语言桥登记

## 3. 关键事实（调查证据）

- `BridgeProvider::call` 只返回 `Value`，无 events/active（`host-core/src/lib.rs:28-32`）
- provider 命中时 exchange 的 events=[]、active=None（`bridge_api.rs:101-111`）
- TS Hub 端点 onEvent 空占位（`hub-stdio.ts:78-80`）；反向 hostCall transport 仅 1:1 安装（`stdio.ts:41-45`）
- Rust provider 能力表只有 echo.ping/echo.upper（`adaptors/rust/endpoint.rs:43`）
- BusFrame 8 帧无事件流/长任务帧（`protocol.json`、`gen/rust/protocol.rs:35-90`）
- `NodeBridgeClient` 是宿主基础对象（handshake/配置加载/动态命令/Hook/host RPC/shutdown 全依赖），不可整体删除，须保留为 Hub 端点的 stdio 传输底层。

## 4. 功能需求（FR）

- FR-1：扩展 `BridgeProvider` 接口，使 `call` 能返回响应 + 有序事件流 + 长任务句柄（替代当前只有 Value 的签名）。
- FR-2：扩展 `BusFrame` 协议与 schema，新增事件流帧与长任务 shutdown 帧；由 `gen.mjs` 重新生成 5 语言绑定；契约检查通过。
- FR-3：`HubBridgeProvider` 用 `attach_command` 真实 spawn 各语言端点（不只用进程内 EchoHandler），并 `announce` 真实业务能力（命名空间前缀，与 `hub-stdio.ts:endpointCapabilities` 对齐）。
- FR-4：`call_bridge` 删除回落分支；provider 失败直接报错，不再 fallback 到 `dispatch_bridge_request`。
- FR-5：TS 侧删除 `LANIA_BRIDGE_MODE` 开关与 1:1 stdio 分支，`stdio.ts` 默认走 Hub 端点；事件通过 publish/event 帧承载；反向 hostCall 走 Hub HostRpcAdapter。
- FR-6：删除 1:1 语言桥登记（`register_python/go/dart/rust_bridge`）及 `NodeBridgeClient` 作为直连 dispatch 的用法；保留其作为 Hub stdio 传输底层的实例。
- FR-7：长任务（dev/watch）经 Hub 承载事件流与 Ctrl-C shutdown follow-up，行为不退化。
- FR-8：同步所有受影响设计文档（bridge-layer / 模块设计与通信 / package-split / envelope 说明）。

## 5. 验收标准（AC）

- AC-1：`cargo test` 全绿；`node scripts/check-bridge-protocol.mjs` 退出 0。
- AC-2：`removal_check` 对废弃符号零残留：`dispatch_bridge_request`、`LANIA_BRIDGE_MODE`、`register_python_bridge`、`register_go_bridge`、`register_dart_bridge`、`register_rust_bridge`、`runStdioBridge`。
- AC-3：`call_bridge` 源码中不存在回落分支（grep 证据）。
- AC-4：`lania-bridge-host/tests/stdio_endpoints.rs` 跨语言集成测试全绿，且覆盖 5 语言端点 announce + request/response + 事件流。
- AC-5：`dev/build/lint` e2e 测试通过（`packages/distribution/cli/rust/lania-cli/tests/phase3_e2e/`）：进度/日志事件可见、watch shutdown 正常。
- AC-6：`source_purity.py check --strict` 退出 0，无 fake adapter/占位。
- AC-7：review_gate Blocker=0；commitment_ledger check --strict 退出 0。
- AC-8：所有 Affected 设计文档同步或显式声明无影响。

## 6. 未决与假设（Open → 进契约 Open 段）

- U-1：go/dart 端点真机验证环境缺失（preflight 报 staticcheck/flutter 缺失），是否阻塞收尾需确认；降级=仅 Rust/TS 真机跑通，go/dart 用生成物契约测试覆盖，登记环境阻断。
