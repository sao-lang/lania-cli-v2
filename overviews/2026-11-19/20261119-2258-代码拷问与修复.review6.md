## 等价性基准澄清（非缺陷，但决定"等价性"结论如何表述）

- git HEAD 基线的命中分支是 `from_cache = false`（HEAD `store.rs:194-195`），bug **仍在基线里**；任务描述所称的"原逻辑（只在 `!cached.is_file()` 时置 false）"是去掉该 bug 后的语义意图，而非 HEAD 实际代码。
- 结论分两层：
  - 新逻辑 vs **正确意图的原逻辑**：所有路径等价 ✓。
  - 新逻辑 vs **HEAD 实际基线**：在"命中缓存"路径**不等价**（HEAD 恒 false → 新逻辑 true）——这是本次修复的目的，属期望改变，**不是回归**。
- 门禁提示：变更说明应写明"本次同时修复了 HEAD 中的 hit 分支 bug"，否则"行为等价性回归"的验收口径会被误读为"新旧必须完全一致"。

## 2. 纯函数语义与 push 完整性

- `all_from_cache`（`store.rs:965-967`）用 `iter().all()`，空切片返回 true，符合原初值 true 语义；`&bool` 解引用写法正确。✓
- push 完整性：唯一 push 点 `store.rs:253`，位于 `if !verified { return Err(...) }`（`248-252`）之后。任何产物的校验失败都会提前返回，**不会带着缺失的 `cache_hits` 继续构造 outcome**。因此不存在"漏 push 却产生结果"的路径，`cache_hits.len()` 恒等于成功处理的产物数。✓
- 但此不变量当前无任何断言或测试保护（见 S1）。

## 3. 测试质量

- 3 个测试（`store.rs:990-1017`）断言正确、非假绿；Verify RED 改恒 false 后 test1（期望 true）与 test3（空→true）失败、test2（期望 false）通过，正好 2 失败，与描述一致，证明测试**对纯函数实现敏感**。✓
- **覆盖盲点**：3 个测试全部直接调用 `all_from_cache`，只锁了"输入→输出"的纯函数语义，**没有覆盖 `install()` 循环里 `artifact_from_cache` 的记录逻辑**（`197-253`）。历史 bug 的复发点恰在循环内（命中分支误置 false / 初值写反）。若有人把 `artifact_from_cache = false` 加回 `if cached.is_file()`（`198-204`），或把初值 `197` 改成 false，3 个测试**全部仍绿**，CI 拦不住。故"已 Verify RED"不等于"bug 复发被锁死"。
- 代码注释 `191` 行"这类写反在结构上无处藏身"表述过强：结构上只是把命中分支的写反挪走了，并未在检验层阻止其回归（见 S1、N1）。

## 4. 分级问题清单

### Blocker

- **未发现 Blocker 级缺陷。** 生产代码在全部关注路径上语义正确，无崩溃、数据损坏或错误输出。

### Should

- **S1 — `store.rs:987-1017`（3 个回归测试）+ `store.rs:197-253`（记录逻辑）**
  - **后果**：回归测试只测纯函数，未覆盖 `install()` 里"文件系统状态 → `artifact_from_cache`"的记录过程。bug 的真正复发点在循环内，一旦被重新引入，86 个测试仍全绿，门禁失效——本轮"补回归测试锁定 bug"的目标未真正达成。
  - **改法**：补一个覆盖 `install()` 的集成测试（预置缓存文件或本地 mock HTTP），断言：①命中缓存 → `outcome.from_cache == true`；②命中但缓存内容校验失败、重下成功 → `from_cache == false`；③部分产物下载 → `false`。若 `install()` 难以在无网络环境驱动，可把 `197-253` 的记录判定抽成一个可注入"命中/校验结果"的纯函数并直接单测，使缺陷无处藏身。

### Nit

- **N1 — `store.rs:189-191` 注释**
  - **后果**："这类写反在结构上无处藏身"过于乐观，与 S1 的盲点矛盾，易让后来者误以为端到端已被锁定。
  - **改法**：改为"收敛到纯函数便于单测锁定汇总语义，循环只负责如实记录每个产物的命中情况"，准确描述保护边界。

- **N2 — `store.rs:960-964` 文档**
  - **后果**：`all_from_cache` 文档称"便于单测直接锁死"，实际锁死的是纯函数语义而非 bug 复发点，措辞可能误导评审。
  - **改法**：在测试中补一行注释说明其保护范围（仅汇总语义），并指向 S1 补齐的集成测试作为复发保护。
